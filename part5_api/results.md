# 大模型 API 实验结果

## 一、校园信息助手测试

### 1. 课程或作业通知

**输入：**

本周五前提交高数作业，作业包括第三章习题1、3、5，请提交到学习平台。

**模型输出：**

一句话总结：

高数作业需在本周五前提交至学习平台，内容为第三章习题1、3、5。

关键信息：
- 截止时间：本周五前
- 作业内容：第三章习题1、3、5
- 提交方式：学习平台

待办事项：
- 完成第三章习题1、3、5
- 于本周五前上传至学习平台

### 2. 活动或讲座通知

**输入：**

本周六下午三点，学校将在图书馆报告厅举办人工智能讲座，欢迎感兴趣的同学参加。

**模型输出：**

一句话总结：

本周六下午三点，学校在图书馆报告厅举办人工智能讲座。

关键信息：
- 时间：本周六下午三点
- 地点：图书馆报告厅
- 事件：人工智能讲座

待办事项：

无

### 3. 学习中的技术问题

**输入：**

Python 中列表和元组有什么区别？什么时候应该使用元组？

**模型输出：**

一句话总结：

列表是可变序列，支持增删改；元组是不可变序列，创建后不能修改。

关键信息：
- 列表用 `[]` 定义，元组用 `()` 定义（单元素元组需加逗号，如 `(1,)`）。
- 列表支持 `append()`、`pop()`、`sort()` 等修改操作；元组不支持任何改变元素的操作。
- 元组可作为字典的键（因不可变），列表不可以。
- 元组在内存占用和访问速度上略优于列表，适合存储固定数据。

待办事项：
- 编程中若数据不应被修改（如坐标 `(x, y)`、RGB 颜色值 `(255, 0, 0)`、函数返回多个值），优先使用元组。
- 练习将常用常量组合（如星期、月份）定义为元组，加深理解。

## 二、提示词对比实验

两次实验使用相同的输入，比较简单提示词和详细提示词的输出。

**测试输入：**

本周五前提交高数作业，作业包括第三章习题1、3、5，请提交到学习平台。

### 1. 简单提示词

**提示词：**

请总结以下通知。

**模型输出：**

通知要点总结：
- **截止时间**：本周五前（含本周五）
- **作业内容**：高等数学第三章习题第1、3、5题
- **提交方式**：通过学习平台在线提交
- **注意事项**：请按时完成并确保提交成功，逾期可能影响成绩。

### 2. 详细提示词

**提示词：**

你是一个校园信息助手，请整理下面的通知。

按照以下格式输出：

一句话总结：

关键信息：

待办事项：

要求：
1. 回答简单清楚。
2. 不要编造原文中没有的信息。
3. 如果没有明确给出时间或地点，写“未提及”。
4. 如果没有待办事项，写“无”。

**模型输出：**

一句话总结：

高数作业需在本周五前提交至学习平台，内容为第三章习题1、3、5。

关键信息：

截止时间：本周五前；

提交方式：学习平台；

作业内容：第三章习题1、3、5；

课程：高数；

地点：未提及。

待办事项：

提交高数第三章习题1、3、5至学习平台（本周五前）。

## 三、简单总结

从这几次测试来看，模型基本能够完成校园通知整理和简单学习问题回答。

使用详细提示词时，输出格式更加符合要求，也能够把需要完成的事情单独列出来。

不过模型有时也会补充原文没有的信息，比如简单提示词中出现了“逾期可能影响成绩”，但原通知并没有说明这一点。

所以我觉得使用大模型整理通知时，最好明确要求它不要编造信息，对于不确定的内容也应该提醒使用者进一步确认。
