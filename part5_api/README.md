# 五、大模型 API 初体验：校园信息助手

## 1. 实验内容

这次实验使用 Python 调用阿里云百炼提供的千问模型，实现一个简单的校园信息助手。

主要完成了三个任务：

- 调用一次大模型 API，检查是否能够正常返回回答。
- 编写校园信息助手，整理校园通知并回答简单的学习问题。
- 使用不同的提示词处理同一段内容，比较输出有什么区别。

## 2. 使用的平台和模型

- 平台：阿里云百炼
- 模型：qwen-plus
- 接口：OpenAI 兼容接口
- 编程语言：Python
- 主要依赖：openai、python-dotenv

API Key 保存在 `.env` 文件中，通过环境变量读取，没有直接写在 Python 代码里。

## 3. 程序说明

### 3.1 API 调用

`api_test.py`

向模型发送“请简单介绍一下什么是机器学习”，并输出模型返回的回答。

程序成功返回了机器学习的相关介绍，说明 API 可以正常调用。

### 3.2 校园信息助手

`campus_assistant.py`

用户在终端输入一段文本，程序将内容发送给模型，并要求按照以下格式输出：

一句话总结：

关键信息：

待办事项：

测试了三种输入：课程作业通知、活动讲座通知和 Python 技术问题。

从测试结果来看，模型基本能够提取通知中的重要内容，也能够回答简单的学习问题。

具体输入和输出记录保存在 `results.md` 中。

### 3.3 提示词对比

`prompt_comparison.py`

使用同一条高数作业通知，分别测试简单提示词和详细提示词。

简单提示词只要求模型总结通知，详细提示词则明确了模型的角色、输出格式和一些限制条件。

## 4. 提示词设计思路

我希望校园信息助手不仅能总结内容，还能把重要信息和需要完成的事情整理出来，所以在提示词中规定了固定的输出格式。

另外，考虑到通知中可能没有写明时间或地点，我要求模型不能自己编造信息。如果原文没有明确说明，就输出“未提及”。

这样可以让结果更方便查看，也能尽量减少错误信息。

## 5. 提示词对比分析

### 5.1 两种提示词的输出有什么差别？

简单提示词能够总结出通知中的主要内容，但是输出格式比较自由，还增加了一些原文没有提到的提醒。

详细提示词按照要求分成了一句话总结、关键信息和待办事项三个部分，内容更加清楚。

### 5.2 哪种提示词的输出更稳定？为什么？

从这次测试来看，详细提示词的输出更符合预期。

我觉得是因为它明确告诉了模型需要做什么、按照什么格式回答，以及哪些内容不能编造。

不过这次只进行了一次对比，还不能确定每次输出都一样。

### 5.3 如果没有明确的时间或地点，可能出现什么问题？

模型有时可能根据自己的理解补充时间或地点，但这些内容不一定正确。

所以我在提示词中要求，如果原文没有明确给出时间或地点，就写“未提及”，提醒使用者还需要确认相关信息。

## 6. 观察到的问题

在简单提示词实验中，模型增加了“逾期可能影响成绩”这句话，但原通知并没有说明逾期是否会影响成绩。

这说明模型有时会根据常识补充内容，而不是完全按照输入文本回答。

另外，在回答 Python 列表和元组的区别时，模型说元组可以作为字典的键，但没有说明元组中的元素也必须是可哈希的。

我觉得使用大模型时不能完全相信它的所有回答，特别是重要通知或技术问题，还是需要自己检查一下。


## 7. 实验总结

通过这次实验，我学会了使用 Python 调用大模型 API，也尝试了通过提示词控制模型的输出格式。

从测试结果来看，详细提示词比简单提示词更容易得到符合要求的回答。

不过模型仍然可能补充原文没有的信息，所以在实际使用时，还需要对输出内容进行检查。
